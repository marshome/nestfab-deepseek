## The virtual-call shape, three times, and one of them names the object

    024040  mov rax, qword ptr [rbx]        ; rax = [rbx] = the vptr
    024043  mov rcx, rbx                    ; **rcx = the object**
    024046  call qword ptr [rax + 0x10]     ; through slot 2

**and the third site cannot be misread:**

    024878  lock sub dword ptr [rbx + 8], 1     ; a std::shared_ptr REFERENCE COUNT
    02487D  je 0x24885                          ; released at zero
    024885  mov rax, qword ptr [rbx]
    024888  mov rcx, rbx
    02488B  call qword ptr [rax + 0x10]

**SO `rbx` IS AN OBJECT, `rcx` RECEIVES IT, AND `EngineBase::run`'s FIRST PARAMETER IS `this`** -- which is the Itanium C++ ABI and which is what this tree said
originally. **What misled last round is that two bodies never DEREFERENCE `rcx`: an absence of member use is not evidence of sret**, and `mov rax, rbx` therefore returns
`this` rather than a buffer address.

**AND THE CLAIM IS CORRECTED IN PLACE** rather than deleted, because the wrong half is worth reading: **the absence of a dereference was treated as a positive
measurement, and it is the third time this session that the absence of a thing was read as evidence of a different thing.**
