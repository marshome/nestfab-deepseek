re: every tool names its encoding -- and the fix that BROKE fourteen files is the reason the fix now has a guard

**THE TRIGGER IS THIS PROJECT'S OWN RULES.** They are written in Chinese and land in commit messages, and the tools read git's output. A `text=True` call with no
`encoding` decodes UTF-8 bytes with the console codepage -- **GBK here** -- so `.stdout` becomes `None`, the caller's next attribute access raises, and
`rounds-must-land-code` reported **"the round-output check did not report a count"** instead of the encoding error underneath it. **That is a rule lying about the
tree**, and it happened the first round a Chinese commit subject landed.

**TEN CALLS HAD IT, INCLUDING `g_rules.py` ITSELF** -- so the checker that runs every other check could die on a bilingual verdict.

## And the first fix broke fourteen files, which is the part worth recording

The replacement was a plain text substitution over `capture_output=True, text=True`, **and it also rewrote calls that ALREADY named an encoding** -- producing
`encoding="utf-8", errors="replace", encoding="utf-8"`. **Fourteen files died on `SyntaxError: keyword argument repeated`, including all five planted-defect
proofs, which exited 1 with NO OUTPUT**: the human's own required proofs, broken by the tool written to make the tools safer. **And `g_fix_encoding_traps.py`
rewrote its own constant**, ending up with an unterminated string, because the pattern it searched for was the pattern it was built from.

**SO THE FIX NOW HAS THE GUARD IT SHOULD HAVE HAD** -- only a call that does not already name an encoding -- **and a second tool whose only job is to prove the
first one's result**: `g_fix_dupe_encoding.py` removes the duplicates and then `compile()`s every `.py` under `re/`, reporting the count rather than the absence
of output. **Zero files fail to compile, and all five proofs run again with `rc=0`.**

**AND THE DETECTOR HAD THE SAME SELF-MATCH**: `g_find_encoding_traps.py` reported its OWN docstring example as a trap, so its pattern is now built from pieces
and its example is prose. **A tool that can match its own text will report itself**, which is the third form of one failure this round: a replacement, a
constant, and a docstring, each edited by the thing that was searching for it.

    re/*.py                     every subprocess call that takes text names its encoding
    re/g_fix_dupe_encoding.py   removes the duplicates and compiles the whole directory
    re/g_find_encoding_traps.py the detector, whose pattern cannot match itself

Gate: build 0 errors 0 warnings, ctest 22 of 22, and the five checks green. Rules: 24, none broken.
