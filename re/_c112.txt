## The field, and the three things that stop it being filled with a guess

    "tool": "g_forwarding_gap.py"   a file that EXISTS in re/
    "tool": "re/vtables.json"       a data file that exists
    "tool": "instruction"           the witness cites an address in the module
    "tool": "measurement"           the witness cites a COUNT over the image, so a re-count falsifies it
    "tool": "unrecorded"            **nobody wrote down what produced this -- a value and not a blank**

* **a value that is not a file in `re/` is REFUSED**, so the field cannot absorb a plausible-sounding word the way a free-text note would;
* **`re/g_provenance.py` re-checks it**, so a script that is deleted or renamed makes its claims fail rather than go quiet;
* **it is `ledger.py check`'s**, the same gate every other claim rule goes through -- **not a separate report nobody runs.**

**AND `ledger.py add` NOW REQUIRES `--tool`**, so a new claim cannot be written without one.

## And the classification itself was wrong twice, in a way worth recording
