re: ONE displacement parser in `lib.py`, because EIGHTEEN scripts spelled it wrong the same way

**THE SCAN FOUND THE FAULT IN 21 LINES ACROSS 18 FILES:**

    g_class_fields.py  g_class_probe.py  g_class_slot_offsets.py  g_class_sites.py  g_class_methods.py
    g_members_without_instructions.py  g_offset_stores.py  g_fill_placeholders.py  g_find_real_ctor.py
    g_find_pool_field.py  g_find_ctor_by_vtable_store.py  g_find_engine_ctor.py  g_flag_widths.py
    g_gen_named_members.py  g_gen_real_structs.py  g_setter_types.py  g_trace_supervisor_ctor.py
    g_types_propagate.py  g_virtual_call_sites.py  g_adjudicate.py  g_trace_timer.py  g_arch.py  g_argshape.py

**EVERY ONE OF THEM WROTE THE SAME PATTERN** --

    (?: \\+ (0x[0-9a-f]+))?

**-- AND CAPSTONE PRINTS A ONE-DIGIT DISPLACEMENT IN DECIMAL.** `[rax + 8]`, not `[rax + 0x8]`. **So offsets 1 to 9 were invisible to all of them**, and `8` is the
module's most common displacement at 44996 occurrences, because it is `vptr + 8`: **the `std::shared_ptr` reference count.**

**AND SIX OF THEM CARRIED THE WORSE HALF**: `if m.group(2)` or `... and m.group(2)`, which turns a memory operand with NO displacement -- `[rax]`, **offset 0** -- into a skip.
**Offset 0 is the table pointer, so those checks could not see a single constructor's vtable store.**

**SO THE FIX IS ONE FUNCTION AND NOT EIGHTEEN EDITS.** `re/lib.py` now has `object_offsets`, which yields `(register, offset, is_store)` and takes both spellings, **and
`displacement`, which returns 0 for `None` rather than treating it as an absence.** **Eighteen private regexes would drift apart again the moment someone writes the
nineteenth script; one function in `lib.py` is what the nineteenth can be told to use** -- and the note above it says so.

**AND `is_store` COMES FROM THE OPERAND'S POSITION**, not from the mnemonic's shape, **because testing the shape is how `re/g_object_access.py` first reported `mov dword
ptr [r13], 0` as a READ.** Three faults, one function, and each of them was found by reporting the wrong answer somewhere else.

## And the first check to be wired was the one the objective names

`re/g_members_without_instructions.py` was parsing with the private regex **AND** the truthy group, so it had both faults at once. With the shared parser its report changes
where it should:

    TimerWinImplementation   +0x0 +0x8                      (was +0x0)
    NestingContextPool       +0x0 +0x4 +0x8 +0xC            (was +0x0 +0xC +0x10 +0x18)
    NoFitMapCanceller        +0x0 +0x4 +0x8 +0xC            (the same)

**the +0x8 baseline pointer and the +0x4 beside it are now visible, and the unsupported count stays 0** -- **so the fix did not create a false alarm and did close a real
blindness.** The rest of the eighteen are reported by `re/g_scan_displacement_readers.py` and are named in this message **rather than quietly left**, because a script that
reads stores is exactly the kind whose output a layout claim would rest on.
