# 可复用的逆向工程能力

**这份文件不是为了这个项目，而是为了下一个。** 它记的是 `re/` 这套东西里**与具体 DLL 无关**的部分——
机制、检查的形状、以及从失败里长出来的规则。任何二进制逆向项目都可以把它整目录拷过去，
换掉四个领域文件，就得到同样强度的约束。

> **一句话前提：逆向工程里最容易发生的不是"不知道"，而是"知道得太早"。**
> 一个字段名想出来了、一个偏移量对了、一段结构看起来合理——**而没有任何东西能阻止它被写进代码、
> 被测试确认、然后在后续四十轮里被当作事实引用。** 下面每一条都是为了在这个链条的某一环上装一个刹车。

---

## 一、四条地基（与领域无关，每个项目都需要）

### 1. 证据分级：`re/ledger.py` + `re/ledger.json`

每条结论是一张记录，带 **grade（等级）** 和 **witness（证人）**，而等级必须配得上证人：

| 等级 | 需要什么证人 | 典型对象 |
|---|---|---|
| `CONSTRUCTOR` | 构造函数写入的偏移（**对象寄存器先确立**） | 类的字段、布局 |
| `INSTRUCTION` | 一条具体指令 + 它的地址 | 一条调用关系的存在 |
| `STRING` | 模块自己的字符串字面量 | 字段名的语义 |
| `DERIVATION` | `__si_class_type_info` 的基类指针 + 模块自己的名字 | 继承关系 |
| `GUESS` | **不允许被上层引用** | 待验证的猜想 |

**关键约束：不同类型的断言只接受特定等级。** `call` 类断言只收 `INSTRUCTION`；
`offset` 类只收 `CONSTRUCTOR`。**这条约束在本项目里抓到了三次"我把自己写的散文当证据"**
（把 `call` 标成 `CONSTRUCTION`，因为它读起来像"构造"）。

**并且：一条错的结论是被**替换**，不是被删除。** 更正留在原地，写清它错在哪——
因为下一个人会踩同一个坑。

### 2. 门禁：一个命令，全绿才能提交

```powershell
re/gate.ps1    # 0 警告 0 错误 → 全部测试 → 五个检查阶段 → 写裁决文件
```

**全绿之前不许提交**，而 `re/g_rules.py` 会检查裁决文件比最新提交新。
**这条把"检查"从"我记得跑一下"变成"提交在物理上做不到绕过"。**

### 3. 每条规则配一个可执行的检查

`re/RULES.md` 存人类原话，`re/g_rules.py` 存**判定程序**。

- **没有检查的规则，就记成"没有检查"**，不打扮成已强制；
- **检查必须能返回三种结果**：通过 / 失败（带证据）/ **无法检查**——
  第三种要打印出来，**因为一个静默失效的检查和没有检查是同一种失败，只是更安静**。

### 4. 每条检查配一个植入式证明：`g_prove_*.py`

> **一个从来没失败过的检查，不知道它是否工作。**

所以每个 `g_xxx.py` 旁边有一个 `g_prove_xxx.py`：**把缺陷植入进去，要求检查失败并点名**；
**同时也植入合法形态，要求检查通过**。

**这一条在本项目里价值最高，因为它抓到了一种最隐蔽的失败：**
`g_full_cpp_audit.py` 的"栈存储"检查报了 0，而两处真缺陷存在——
**因为它的植入式证明里写的形状是"注释里带指令文本"，而仓库里真实的注解写的是 `RE 0xD062`（地址）。**
证明通过了，检查却对着错误的形状。

> **一个夹具是"仓库不会产生的形状"的证明，对仓库什么都没证明。**

## 二、六种可移植的检查形状

这六种与领域无关，任何二进制逆向项目都能照搬。**每条后面是它在哪次真实失败中诞生。**

### 1. 位置伪装成名字
```
正则：\bat_[0-9A-Fa-f]{4}\b | field[0-9A-Fa-f]+ | opaque[0-9A-Fa-f]+ | unnamed[0-9A-Fa-f]+
```
**一个字段的名字如果是它自己的偏移，它就没有名字。** 允许**暂时**用它（模块没给 oracle），
但必须记进账本**并**注明"等 oracle"。

### 2. 宽度来自错误的存储
**读注解里的 `RE 0xNNN`，反汇编那个地址，看它的目的操作数。**
`[rsp + N]` 永远不是对象；`[rbp + N]` **要看 prologue**——
`push rbp` / `mov rbp, rcx` 意味着 `rbp` 持有对象。

> **但只有"宽度主张"该门禁**：`narrowest store is 1 byte` 是在说尺寸，
> 而 `RE 0x5C4A45: a fixed-degree ANGLE` 只是在说值从哪来。**后者引用栈存储是正当的。**
> 一个标记正确代码的检查会被关掉——本项目那次就报了 0。

### 3. 偏移补偿（`+ gap`）
```python
# 一个非零的 *gap* 常量，且被 `member + 常量 == moduleOffset` 消费
```
> **一个需要算术才能到达的偏移，是模型没有的偏移。**

配对的另一半是合法形态：`kDefaultStubGap = 0x10` 量的是**镜像里两个 stub 的距离**，
不参与 `member + gap`。**只查常量会误伤它，所以必须两半一起查。**

### 4. 同一个类有两份描述
```python
# 找 struct/enum 的名字在多于一个头文件里被定义；找 `using X = X_t*` 与 `struct X` 并存
```
**`using Order = Order_t*` 和 `struct Order` 共存时，签名里的 `Order*` 会静默变成 `Order_t**`**，
而包装函数就无法命名它被交给的对象——**这就是 `void*` 擦除的真正来源。**

### 5. 只有名字和析构函数的"类"
```python
# struct/class 的方法体里只有一个 `~X() = default;`
```

### 6. 声明与构造函数写入的偏移对不上
**逐类比较：声明了哪些偏移、已恢复的构造函数实际写了哪些。**
**这是问"这个类是不是缺了字段"的唯一办法**——而它正是 `Nester` 那次失败。

## 三、从失败里长出来的四条方法论

**这四条不是检查，是做事顺序。它们比检查更难自动化，也更有用。**

### 1. 对象寄存器先确立
**一条存储指令的偏移，只有在它的基址寄存器确实是对象时才构成证据。**
`mov rcs, rcx` / `mov rbx, rcx` 是确立动作；**没有它之前，任何偏移都只是数字。**

### 2. 同一族里更小的那个构造函数是基类
`0xB4470`（29 字节，5 个调用者）是基类；`0xB4DA0`（43 字节，7 个调用者）
**做完了前者再做一步 qword 移动**——所以它是**共享同一基类的另一个派生类的构造**。

> **判定一个类属于哪一族，靠的是它**调用者的自有偏移**：**
> `0xB4470` 的 5 个调用者都在 `+0x18` 写第一个自有成员，`0xB4DA0` 的 7 个都在 `+0x20`。
> **两个族，两个基类部分大小。**

**我第一版读错了基类，多加了 8 字节，把每个派生成员推后 8 字节——测试一次构建就抓住了。**

### 3. 顺藤摸瓜要按"调用者最多"和"链最长"排，不按函数最小
- **调用者最多 = 根。** 恢复一个解释成百上千个调用点；
- **链最长 = 真实工作量。** 一个 36 字节的入口跳进 757 字节，**那是 757 字节的逆向**；
- **而 `jmp qword ptr [rip + ...]` 加 `nop` 填充是导入 thunk**，链在模块外断掉，逆向不了。

**本项目实测：128 个未反转的导出，链上没有一个函数小于 64 字节——"容易的先做"在这里不成立。**

### 4. 一次只改一件事，而且改完立刻让机器说话
- **改名和改宽度不能在一步里做**（一次既改名又改宽度，是两件事假装成一件事）；
- **`reinterpret_cast` 只出现在 ABI 边界**，实现函数收真类型；
- **删一个成员之前先问：谁读它？** `WindowSlots` 的八个槽位只有两个被读，
  **其余六个是为了满足 `static_assert` 而维护的"没人用的假设"。**

## 四、拷贝清单：下一个项目要带走什么

```
re/
  gate.ps1                    一个命令，全绿才能提交
  g_rules.py                  规则 → 可执行检查（三态：通过/失败/无法检查）
  g_prove_*.py                每条检查的植入式证明（必须两侧都钉）
  ledger.py + ledger.json     证据分级，错的被替换而非删除
  g_note.py                   记录人类的要求和决定，带轮次
  g_rounds.py                 每 30 轮与人类同步（独立于 push）
  g_backup.py                 远端不可达时的已验证 bundle
  g_land.py                   精确块替换（拒绝非恰好一次匹配）
  g_gap_compensation.py       ← 从本项目带走的检查 ①
  g_stack_annotations.py      ← ②（宽度主张 vs 值主张）
  g_full_cpp_audit.py         ← ③（六种形状）
  g_hot_functions.py          ← ④（按调用者数排序找根）
  g_chain_size.py             ← ⑤（按链长排序找真实工作量）
  g_base_ctor.py              ← ⑥（读构造函数 + 列调用者）
  g_missing_base.py           ← ⑦（找补偿性常量）
```

**而这四个要换掉**（领域相关）：`RESUME.md`、`RULES.md`、`DECISIONS.md`、`LEDGER.md`。

## 五、这套东西最常见的失效方式

按本项目实际的失败频率排序：

| 失效 | 症状 | 解药 |
|---|---|---|
| **检查太窄，报 0 而缺陷存在** | 全绿，但人类一眼看出问题 | 每条检查有植入式证明，**且夹具必须是仓库真实产生的形状** |
| **计数是"某个正则的计数"** | 数字漂亮，与机制无关 | 数**机制**（包装到底调没调实现），不数模式（清单里有没有名字） |
| **工具删掉了它不该删的** | 断言 217 行消失，只有 `check_recovery` 察觉 | 重写一段**不是自己创建**的文本时，先数前后各类证据的条数 |
| **改一处、动全身** | 一个字段的补充让整个派生族偏移 | 布局测试**逐字段**断言模块偏移，而不是只查总大小 |
| **把自己写的散文当证据** | 注解里的 `+0x1C` 被当成字段偏移 | 偏移注释**行内**，且解析器只认行内形式 |
| **反汇编器的文本格式被当成语法** | 某个偏移在**多个互不相关的类里同时**"没人用" | **位移按数值解析，不按拼写匹配**；见下 |
| **否定结论被当成正面测量** | "这里没有 X 的用法" → "所以它是 Y" | 不存在**只能**支持"未解"，不能支持"是别的东西" |

### 「多个不相关的类同时出事」是读法器错了的信号

**这一条值得单独写，因为它每次都长得像领域发现。** capstone 对**单个十进制数字**的位移省略 `0x`：`[rax + 8]`，而对更大的是 `[rax + 0x10]`。于是一个要求 `0x` 前缀的解析器**在偏移 8 上什么也看不见**——而偏移 8 是全模块**最常见**的位移（44996 次，`vptr+8`，每个 `shared_ptr` 的引用计数）。同样被漏掉的是 1..9（3453 / 3021 / 1027 / 787 / 624 / 581 / 524 / 145 次）。

**症状的形状**：一次报告里**九个互不相关的类**都在 `+0x8` 上有"没人访问的成员"。**判据**：如果同一个偏移在**多个互不相关的类**里同时失效，**错的是读法器，不是那九个类**。**一个真实的缺陷是局部的；一个解析错误是全局的。**

**同样常见的是把"没找到"读成"是别的"**：本项目在 `rcx` 是 sret 还是 `this` 上错了两次方向——第一次因为两个函数体从不解引用它（**那只是"没有成员使用"**），第二次因为四个函数体都会解引用（**那只是"有可能"**）。**裁决它的是调用点**（`mov rax, [rbx]` / `mov rcx, rbx` / `call [rax + 0x10]`，旁边还有 `lock sub dword ptr [rbx + 8], 1`）——**一个正面测量**。**否定结论只能支持"未解"。**

## 六、这份文件本身怎么维护

**不要在这里复制 `re/RULES.md` 的内容。** 那是两份会漂移的同一规则——
**而这个项目已经有 `g_duplicates.py` 专门抓这件事。**

这里放的是**跨项目不变的东西**：机制的形状、失败的类型、做事顺序。
**项目特有的每一条，都属于那个项目的 `RULES.md`，带它自己的检查、轮次和人类原话。**
