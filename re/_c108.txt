**NINE UNRELATED CLASSES, ALL AT `+0x8`, AND NOTHING IN THE MODULE TOUCHING IT.** The shared offset is the tell: **a real defect is LOCAL and a parsing error is GLOBAL.**

**AND THE CAUSE IS HOW CAPSTONE SPELLS A DISPLACEMENT:**

    8      44996 occurrences      <- NO `0x` PREFIX
    1       3453      4       3021      2       1027      7        787
    3        624      6        581      5        524      9        145
    0x10, 0x18, 0x20, ...        <- every larger one IS prefixed

**a ONE-DIGIT displacement is printed in DECIMAL and everything larger in hex**, so a regex demanding `0x` sees offset 8 NOWHERE -- **and offset 8 is the most common displacement in the whole module, because it is `vptr + 8`: the `std::shared_ptr` reference count.** The same reading is in `re/g_arch.py`, `re/g_argshape.py`, `re/g_52f8.py`, `re/g_62f280.py` and `re/g_anchor_angle.py`, **so offsets 1 to 9 have been invisible to several checks this project has trusted.** `[rax]` with no displacement is offset 0 and has the same effect on vtable stores -- **the same blindness `re/g_members_without_instructions.py` had two rounds ago.**

## And with the spelling fixed the answer is ZERO, which is a negative result about the QUESTION

**36068 distinct displacements occur somewhere in the module and every small offset is among them**, so a module-wide search cannot separate a declared member from anything
else. **The check that CAN answer it is `re/g_members_without_instructions.py`**, which pairs a class with a function (its destructor) and then asks whether the object is
touched **through that function's own object register** -- **class attribution is what the module-wide search lacks, and without it the answer is "somebody, somewhere" rather
than "this class".** The tool says so instead of reporting a clean bill of health.

**AND BOTH LESSONS GO INTO re/REUSABLE.md**, because neither is about this library: **parse a displacement as a NUMBER and never as a spelling**, and **when the same offset

"it is something else"**, which is the mistake this session made twice about whether `rcx` is an sret buffer.
