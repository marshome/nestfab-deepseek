lcns: the engine `run` bodies say the BASE SIGNATURE IS WRONG -- `rcx` is an sret buffer for two of them, and all six take a FIFTH argument

**THE OBJECTIVE'S ORDER IS "read the constructor, establish the object register, then the vtable slots", AND FOR THE ENGINES THE OBJECT REGISTER IS THE FIRST THING THAT
DOES NOT HOLD.** `EngineBase::run` is declared as

    virtual void* run(const void* problem, double timeLimit, void* observer, void* result) = 0;

**four arguments after `this`** -- and the module does two things that signature cannot do.

## One: for two of the six, `rcx` is an SRET BUFFER

    756ED9  movsd xmm0, qword ptr [rdx + 0x20]      ; the problem is in rdx
    756EEA  mov rdi, rcx                            ; **rcx saved**
    756F1C  mov dword ptr [rdi], 0                  ; **written through -- a RETURN BUFFER**
    756F2F  mov qword ptr [rdi + 0x10], 0
    756F37  mov qword ptr [rdi + 0x18], 0
    756F87  mov qword ptr [rdi + 0x18], rsi          ; the fifth argument placed in it
    756FBC  lea r8, [rdi + 0x30]

**and `InfiniteEngine::run` and `EquivalentEngine::run` do the same, while `MultiEngine`, `DelayedEngine`, `NestingEngine` and `CompositeEngine` DO dereference `rcx` and
cannot be told apart from `this` by this test.** **So the family is split** and the split is recorded rather than averaged.

**AND IT EXPLAINS `InfiniteEngine`'s `mov rax, rbx`**: `rbx = rcx`, **so the function returns the SRET POINTER, which is what the C++ convention requires** -- and the
tree's comment reads that instruction as evidence that the return value is `this`. **It is evidence of the opposite.**

## Two: every one of the six reads a FIFTH argument from the stack

    759A94  mov r9, qword ptr [rsp + 0x60]     ; **in a function whose prologue is `sub rsp, 0x30` and `push rbx`**

**read after the prologue, so it cannot be a local** -- and all six read a `[rsp + N]` above their own frame.

**AND THE TWO FINDINGS ARE ONE PROBLEM**: a method with a `this` and four more arguments **has no room for an sret pointer**, so a signature with four arguments AND a
`this` first cannot describe a body that writes a return buffer and reads a fifth argument. **`read the constructor, establish the object register` is the rule, and here
the FIRST register was wrong for two of the six -- which is why the rule is first.**

**AND THE FIX IS NOT MADE THIS ROUND.** The right signature takes establishing: how many arguments, which are the sret and the object, and whether the four that DO
dereference `rcx` are also sret with an argument the test cannot see. **What this round establishes is that the declaration as written is contradicted by six bodies**,
which is enough to stop it being quoted as settled.
