## 7. **缺陷缩减公式的形态已读出**（goal round 30）**[已证实为指令序列；语义为推断]**

`EquivalentSmallerDefects`（`0x4BC9E0`，1,677 B / 382 条指令）里浮点常量的用法可逐条读出：

```
4BCA3C  call 0x4F9C30            ; X = f(...)
4BCA44  xmm9 = 0.5               ; ← 常量 0.5
4BCA4D  xmm6 = xmm0              ; 存下第一个结果
4BCA51  call 0x5C6100            ; W = g(...)
4BCA56  mulsd xmm9, xmm8         ; 0.5 × xmm8（xmm8 早先由 xmm2 保存）
4BCA5B  subsd xmm6, xmm9         ; xmm6 = X − 0.5·W
4BCA60  ucomisd xmm6, xmm7       ; 与 0 比较（xmm7 = pxor 出来的零）
```

⇒ **缩减量 = X − 0.5·W**，并与 0 比较 —— 这正与该函数自己的断言
`'defect_reduction > 0.0'`（`0x4BC9E0`）**互相印证**：缩减量必须为正。
第二处常量 **`4`**（`0x4BCD96` 载入 `xmm3` 后调用辅助）⇒ 另有一个 **4 倍**因子参与其中。

**同族的 `0x4BAC30`（345 B）**：**入口第一条浮点指令**就把 **`0.2`** 装进 `xmm1`，随后
`call 0x4BABA0` 并 `test al,al` ⇒ **`0.2` 是被传给子过程的参数（权重/容差）**，不是它自己算出来的值
（Windows x64 下 `rcx`/`rdx`/`r8` 已占三个整型参数，`xmm1` 即第 4 个参数）。

**尚未解**：`X` 与 `W` 各自的具体来源（`0x4F9C30`、`0x5C6100` 两个被调用者的语义）、`4` 倍因子用在哪个分支、
以及 `0.2` 在子过程里如何参与判定。**没有**把它当作"公式已恢复"——目前只确定**形态**。

## 8. 缩减法：`X` 与减项都定下来了，并**更正上一节的一处措辞**（goal round 31）**[已证实]**

两个被调用者读出来是**极小的 getter / 初始化器**：

```
0x4F9C30  (6 B, 2 ins)   movsd xmm0, qword ptr [rcx + 0x58] ; ret
        ⇒ 单字段取值器：X = obj->[+0x58]（double）

0x5C6100  (24 B, 4 ins)  mov qword [rcx],0 ; mov [rcx+8],0 ; mov [rcx+0x10],0 ; ret
        ⇒ 把一个 24 字节的三元组（= 三维点/向量）清零，无返回值
```

**更正**：上一节我写"`W = g(...)`（`0x5C6100`）"，把它当成了减项的来源 —— **不对**。
`0x5C6100` 没有浮点返回值（它只清零内存，是**副作用**调用）。真正的减项是 **`xmm8`**，
而 `xmm8` 在此前由 **`xmm2`（传入的第三个浮点参数）** 保存而来。

⇒ 因此公式应写为：

```
reduction = obj->[+0x58]  −  0.5 × (第三个浮点参数)
断言：reduction > 0.0        （'defect_reduction > 0.0'，同一函数）
```

`0x5C6100` 的角色是**为后续使用把某个三维点清零**（准备输出），与减项无关。

**尚未解**：`+0x58` 这个字段的语义（是"缺陷面积"还是别的度量）、第三个浮点参数的来源与含义、
以及 `0x4BCD96` 处那个 **4 倍**因子所在分支。

全**可达集**范围扫描 `movsd ..., [reg+0x58]`（写 8 字节）⇒ **103 个函数**命中。排在最前的是**构造 API**：

|---|---:|---|

| `0x13800` / `0x13A50` | 581 / 569 | **`AddHoleToPart`** |
| `0x15480` | 404 | **`AddCircularPart`** |
| `0x15620` | 374 | **`AddRectanglePart`** |

| `0x16B20` | 353 | **`AddNonRectangularPolygonSheet`** |
| `0x827F0` | 5,274 | 引擎 supervisor（`module.engine`） |

⇒ **语义推断（证据充分）**：`+0x58` 是**零件/板材级别的几何标量**，由**所有 `Add*` 构造入口**写入，
被 `EquivalentSmallerDefects` 当作 `X` 读取。候选含义：**面积 / 外边界长度 / 缺陷度量**。

**与既有恢复的交叉印证**：登记表里 `model.item_unknown_fields` 那条写明

现在又知道它**由 `Add*Part`/`Add*Sheet` 写、被等价缺陷缩减读**。这把这个字段从"已知偏移"推进到
"**有写入者与读取者的字段**"，是 `model.item_unknown_fields` 可以缩小的一步。

**仍未定**：`+0x58` 到底存的是面积、边界长度还是别的度量（要读 `AddRectanglePart` 里给它赋值前算的是什么）；
以及 `0x4BCD96` 处的 4 倍因子分支。

## 11. **更正**：第 10 节的写入者清单是错的（goal round 34）**[已证实]**

第 10 节我声称"`+0x58` 由 `Add*Part`/`Add*Sheet` 构造 API 写入" —— **这是错的**。
原因：那次扫描用 `mem.disp == 0x58` 匹配，**没有区分基址寄存器**，于是把
**`[rsp + 0x58]`（栈上局部变量）**也算了进去。逐条回看两处写入点即可看出：

```
0x1569C  movsd qword ptr [rsp + 0x58], xmm0     ; 这是栈局部，不是对象字段
0x13457  movsd qword ptr [rsp + 0x58], xmm6     ; 同样是栈局部
```

⇒ **第 10 节的"写入者是构造 API"结论作废**，其表格与推断不再有效（本条保留在文档里就是为了让读者
看到这次错误与更正，而不是被悄悄改掉）。读取侧不受影响：`0x4F9C30` 是 `movsd xmm0, [rcx + 0x58]`
（`rcx` = this 指针），**那确实是对象字段**。

**修正后的扫描**（排除 `rsp`/`rbp` 基址）结果见本轮输出；被排除的栈写入 **69 处**。
**教训**：字段偏移扫描必须**限定基址寄存器**，否则栈局部会污染结果 —— 与之前
"候选列表没按可达性过滤"是同一类错误：**过滤条件写少了，结论就会系统性偏移**。

## 12. `+0x58` 属于**一段连续 double 记录**，被整体拷贝（goal round 35）**[已证实为指令序列；语义为推断]**

`0x827F0`（引擎 supervisor，5,274 B）与 `0xABEC0`（`_reduced` 族，4,882 B）里对 `+0x58` 的写入**逐条相同**，
是一段**逐字段结构拷贝**：

```
rdi = 源对象, r15 = 目标对象
82ECA  movsd xmm0,[rdi+0x48] ; 82EDA movsd [r15+0x48],xmm0
82ED3  mov rbx,[rdi+0x98]    ; 82EE5 sub rbx,[rdi+0x90] ; 82ECF mov [r15+0x38],rbx
82EE0  movsd xmm0,[rdi+0x50] ; 82EEC movsd [r15+0x50],xmm0
82EF2  movsd xmm0,[rdi+0x58] ; 82EF7 movsd [r15+0x58],xmm0      ← 本字段
82EFD  movsd xmm0,[rdi+0x60] ; 82F02 movsd [r15+0x60],xmm0
```

⇒ **结构结论（证据充分）**：`+0x58` 是**一段连续 double 记录（`+0x48`/`+0x50`/`+0x58`/`+0x60`）中的一格**，
该记录**被整体拷贝**；同一条记录里还有 **`[+0x90]`/`[+0x98]` 的 `[begin,end)` 指针对**，
其**差值被存到 `+0x38`**（`+0x98 − +0x90`）⇒ 这是一个**带容器大小与若干 double 计量的记录**
（很可能是统计/度量块：面积、已用表面、比率、计数之类）。`0x8FF70` 里也是同类的**按 8 字节逐格拷贝**。

**一处重要澄清（撤销我上一轮的"冲突"说法）**：我上轮说"lcns 把 `Part+0x58` 登记为 bool、
而原库这里是 double，二者不可能同时正确"。现在看，**这未必是冲突** —— `+0x58` 属于**另一个结构**
（上述度量记录），不同结构可以有相同偏移。所以正确表述是：
**"同一个偏移 `+0x58` 至少出现在两个不同结构里"**，而不是"lcns 的偏移错了"。
要判定 lcns 的 `Part+0x58` 是否错误，必须**先确定读取它的那条路径用的是哪个结构**（`0x4F9C30` 的 `rcx` 来自
`EquivalentSmallerDefects`，属于等价问题一侧，**大概率不是 `Part`**）。

**仍未定**：那四个连续 double 各自是什么计量；`[+0x90,+0x98)` 容器的元素类型。

## 13. 两个 `+0x58` 数字并存，各有各的问题（goal round 37）**[已证实]**

用新的 `covlib.field_writes_scan` 复核时得到 **810**，而第 11 节的更正是 **46** —— **不是矛盾**，
两次问的问题不同，必须写清楚：

| 数字 | 查询条件 | 含义 |
