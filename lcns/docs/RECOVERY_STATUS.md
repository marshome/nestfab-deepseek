# 逆向状态总表（由 `include/lcns/recovery.hpp` 生成）

本工程把代码分成五种状态，**每一处在源码里都有一个可 grep 的标记**，
并与 `recovery.hpp::kGaps` 登记表逐条对应；`tools/check_recovery.py` 强制「代码标记集合 == 登记表集合」，且带具体 RVA 的缺口必须出现在 `re/` 文档中。

| 状态 | 含义 | 条目数 |
|---|---|---:|
| `Recovered`（已恢复） | instruction-level faithful; constants cite RVAs checked by tests | 9 |
| `Structural`（结构已恢复） | structure/algorithm skeleton recovered; body re-implemented | 20 |
| `Substituted`（替代实现） | the original uses something unavailable here, or heuristic constants were NOT recovered | 28 |
| `NotReversed`（**尚未逆向**） | feature exists in the DLL but has NOT been reverse engineered (the only macro that means this) | 13 |
| `NotInBinary`（非原库） | our own extension | 1 |

> 未逆向 ≠ 未知：凡是标为 `NotReversed` 的，都给出了它在二进制中的地址（或明确写了"-"），说明它**存在**但我们**没有译出**；凡是 `Substituted` 的，说明这里跑的是**替代实现**，不是原库算法。
